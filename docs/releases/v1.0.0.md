forgesync now syncs Linear issues too. Issues come from **providers**, GitHub
and Linear: each Notion Project names its provider and is matched on its
`repo` (GitHub) or `teamKey` (Linear). One run syncs both, and a provider that
fails no longer stops the other.

This is a breaking release. The Notion schema, the config rules, and the JSON
output all change, so read the [upgrade path](#upgrade-path) before running it.

## Breaking changes

### Notion schema

v1.0.0 needs a migrated workspace, and v0.12.0 stops working on one, so
migrate right after updating and don't run v0.12.0 in between. Back up both
databases first (`•••` → Export → CSV).

**Projects database**

1. Add a **Select** property named `provider` with two options, `GitHub` and
   `Linear`.
2. Set `provider` to `GitHub` on every existing Project. A Project left empty
   is skipped and reported as `project has no provider`; on an unmigrated
   workspace that's every Project, so nothing syncs.
3. Add a **Text** property named `teamKey`. Leave `name` and `repo` as they
   are.

**Stories database**

4. Change `Issue` from **Number** to **Text**. Notion keeps each value as its
   plain number (`12`).
5. Rewrite every value as `#12`, in Notion itself (a table view filtered on
   `Issue` is not empty helps). Don't export and re-import a CSV: that creates
   new pages and loses their Project relations.
6. Check that a filter `Issue` does not start with `#`, plus is not empty,
   shows no rows. A value without `#` no longer matches its issue, so the next
   sync would create a duplicate Story.

**Linear Projects** (only if you'll use Linear)

7. Create one Project per Linear team, with `provider` set to `Linear`, the
   team's key in `teamKey` (e.g. `ENG`, the prefix of its issue identifiers),
   and `repo` empty.

The full property list is in
[Notion setup](https://github.com/nox456/forgesync/blob/v1.0.0/docs/NOTION_SETUP.md).

### Config

`github_token` is no longer required on its own: the config needs at least one
of `github_token` and `linear_token`. A config with only `github_token` keeps
working as before.

### JSON output

| Command    | v0.12.0                                                                                            | v1.0.0                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `projects` | `name`, `repo`                                                                                     | `name`, `scope`, `provider`                                                                                                    |
| `issues`   | `number`, `repo`, `title`, `has_linked_pr`                                                         | `identifier`, `scope`, `title`, `has_linked_pr`, `provider`, and a top-level `errors`                                          |
| `status`   | `issue_number`, `issue_title`, `project_name`, `issue_repo`, `status`, `has_pr`, `is_synced`       | `identifier`, `issue_title`, `project_name`, `scope`, `status`, `has_pr`, `is_synced`, `provider`, and a top-level `errors`    |
| `sync`     | `errors`: strings, or `null` when empty                                                            | `errors`: objects, `[]` when empty                                                                                             |

Field by field:

- `number` and `issue_number` (integers) → `identifier` (a string): `#12` on
  GitHub, `ENG-123` on Linear.
- `repo` and `issue_repo` → `scope`: the repo (`owner/name`) on GitHub, the
  team key on Linear.
- New `provider` on every project, issue, and status row: `github` or
  `linear`.
- New top-level `errors` array on `issues` and `status`.
- Every `errors` entry is an object, `{"provider", "project", "identifier",
  "message"}`. `message` is always there; the other three only when they
  apply.

From v1.0.0 the JSON output is a stable contract under semantic versioning:
removing or retyping a field means v2.0.0. The
[README](https://github.com/nox456/forgesync/blob/v1.0.0/README.md#json-output)
lists every field.

### Text output and exit codes

- The `projects`, `issues`, and `status` tables start with a `Provider`
  column. `projects` shows `Scope` instead of `Repo`, and `issues` shows
  `Issue` and `Scope` instead of `#` and `Repo`.
- Issue identifiers print as `#12` (they printed as `12`).
- Error lines name the provider and identifier (`* github #12: …`), the
  Project (`* Team project: linear token not configured`), or just the
  provider (`* linear: linear api 401: …`). They used to read
  `* forgesync#12: …` whatever the repo.
- `issues` and `status` print an `Errors:` section after the table.
- `sync` no longer exits 1 when GitHub fails: the failure is listed under
  `errors`, the run exits 0, and Linear still syncs if it's configured. Notion
  errors still exit 1. `issues` and `status` exit 1 only when every provider
  fails.

## New

- **Linear support.** Set `linear_token` (or `FORGESYNC_LINEAR_TOKEN`) to a
  Linear personal API key. Linear issues assigned to you and updated in the
  last 7 days sync into the Project whose `teamKey` matches, triage issues
  excluded. Their status follows the issue's workflow state type and always
  overwrites a status edited by hand in Notion; see the
  [status mapping](https://github.com/nox456/forgesync/blob/v1.0.0/README.md#status-mapping).
- **`--provider github|linear` and `--team KEY`** on `sync`, `status`, and
  `issues`, and **`--repo`** on `issues` too (it was `sync` and `status`
  only). Combinations that contradict each other are rejected before any API
  call; see
  [Choosing providers](https://github.com/nox456/forgesync/blob/v1.0.0/README.md#choosing-providers).
- **Problems are reported, not fatal.** A provider that fails is listed under
  `errors` and the other keeps going. So is a Project with no provider, an
  unknown one, or a provider you have no token for.

## Fixes

- `sync --json` printed `"errors": null` when there were none; it's now `[]`.
- Text error lines no longer hard-code `forgesync#N`, and Notion write errors
  now say which provider and Project they belong to.
- A Project with an empty `name` or `repo` no longer crashes the run with
  `index out of range`.
- Command errors were printed twice; they're printed once.
- The unused internal `Priority` field is gone. `Prioridad` in Notion was
  never read or written, and still isn't.

## Upgrade path

1. Run `forgesync update`, or reinstall with the install script or
   `go install github.com/nox456/forgesync/cmd/forgesync@v1.0.0`.
2. Migrate Notion straight away, following the [checklist](#notion-schema)
   above.
3. Optional: add `linear_token` and your Linear Projects.
4. Run `forgesync sync --dry-run` and compare its counts with your last
   v0.12.0 run. `Created` should only count issues that never had a Story;
   extra creates usually mean an `Issue` value missing its `#`.
   `forgesync status` shows where each issue lands.
5. Run `forgesync sync`.
